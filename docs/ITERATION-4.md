# 修正：自动分类与作业可见性

用户明确纠正：标签默认自动分类，不是先手工创建。本轮保留手工标签作为补充标记，不再要求先建课程标签才能看到分类。

## 已查明

实际运行的上版独立目录已连接学校，但数据库仅有 51 个 Gmail 候选，没有 Moodle 来源事项；学校采集状态 error。正式列表空不是“没有作业”或“全部完成”。原运行目录只读排查，不覆盖正在使用的数据。

冻结采集子进程 exit1、stdout为空，异常栈在 moodle_process.main 的 JSON 输出行。中文输出在 Windows cp1252 管道下可确定性重现 UnicodeEncodeError；旧离线诊断仅用了 ASCII 错误结果，没有覆盖真实中文作业。改用 ASCII JSON 传输，解析后的原中文完整保留。

## 实施

- 根据来源课程身份、作业／测验／考试／活动类型和标题内明确小组自动生成标签。未知课程标为待识别，不猜小组归属，不启用模型。
- 使用 course_site＋course_id 区分同名课程；历史无ID资料以课程名称标注旧身份。中文课程、无截止作业仍显示。
- 自动标签作为派生 JSON 元数据，不新开数据库服务、不新增关系表；手工标签保留独立。同步自动更新派生标签；既有业务版本、历史安排、候选核对状态不因回填递增。
- 作业页显示分类／课程筛选与分类概览，正式事项和待核对邮件分开切换；学校同步失败显式解释，不让空列表误导为没有作业。
- 校验真实学校只读采集、合成页面桌面／手机、全量回归、便携中文输出、源码及数据副本回滚，再单独交付新版。

Ruling: 自动分类先用可追溯来源与明确文字规则，不调用模型或自动确认邮件 — 防止误分后产生截止提醒 — 成本：含糊课程／组别仍显示待识别。

Ruling: 既有原始正式列表接口保持兼容，页面另取候选列表；邮件候选可见不等于正式作业 — 保持提醒隔离 — 成本：页面多一次小型元数据查询。

Ruling: 以派生自动标签加独立手工标签实现自动优先；升级前备份并保留旧版包 — 成本低且可回退 — 成本：自动标签不是人工自由删除的目录条目。

## 收尾记录

- AI 仅保留 authenticated API/adaptor，默认 disabled，无模型调用，无额外 TCP 监听端口。
- 实际学校只读采集恢复返回 57 个事项（12 作业、41 测验、4 其他）；部分权限及状态读取仍失败，页面保留不完整同步提示。
- 一次独立审阅发现两个重要问题：总览标题点击引用未定义变量；同主机不同 Moodle 安装路径课程范围碰撞。均补测试 RED→GREEN 修复。
- Final: minor (deferred): 英文 Group A/group a 同标题大小写差异可能显示组别冲突；保守待核对，不合并不确定归属。
