# 学校登录回调诊断（2026-10-13）

追加修复：已在实际失败进程确认 Windows 传入地址末尾增加 `/`，使 Base64 长度余数为 1，导致严格解码失败。仅在此形态下移除额外的一个尾斜杠；合法 Base64 自身的 `/` 保留。继续验证原来的 passport 指纹、后台会话、有效期与一次性使用。回归测试覆盖原始、带尾斜杠、百分号编码尾斜杠、合法 Base64 尾斜杠及重放拒绝。

实际接口验证：修正回调形态后，旧 urllib 请求组件在读取学校 REST 响应时出现 TimeoutError。使用同一授权、直连和 HTTPX 请求方式取得 HTTP 200 的 JSON 响应，确认有效 userid，未输出账号或令牌。默认 Moodle 请求组件已改为项目现有的 HTTPX，并通过实际 MoodleClient 验证账号资料及课程列表读取，保持禁用系统/环境代理、验证 HTTPS 证书和只读函数白名单，不增加新依赖。接口读取成功不代表旧的已失败授权流程已在工作台完成；升级后需从当前工作台重新发起授权。

此版本补齐回调失败提示和安全记录。此前学校登录后唤起 EXE，如果本机回调失败，程序会直接退出，导致只看到白屏且工作台继续等待。该现象的具体学校端原因仍须通过新的一次实际授权验证，不能以自动化回调测试代替本人登录。

关闭旧后台，保留原来的 config.json 和 data，完整覆盖新版程序文件再启动。在当前工作台重新点击“学校网页登录”。旧白屏页面以及超过十分钟的授权不可用于新的一次登录。

学校授权回传后：

- 成功时工作台会通过现有轮询刷新连接状态。
- 失败时显示中文错误窗口，说明过期授权、本机后台不可达或学校移动接口的拒绝类别。
- `data/moodle-login-result.json` 只记录时间、成功与否、HTTP 状态及枚举错误类别；不记录令牌、原始回调、账号或学校返回正文。

以前临时使用的 Python 诊断回调已恢复为正常 EXE 入口。发布包不依赖该临时诊断脚本，也不需要系统 Python。
