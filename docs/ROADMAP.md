# Academic OS 迭代路线

2026-10-13。采用现有 Python、SQLite、FastAPI 和原生 JS 增量迭代，不另起状态库。

## 当前基线

原始交接源码已独立导入 main（`0f2a85c`），离线测试 150 项通过。此后迭代使用分支与 PR；个人邮件、数据库、运行配置、令牌及历史备份不纳入 Git。

## 迭代 1：来源可靠性与邮件查询

- [x] 邮件主入口、全库分页、账号／关键词／收件日期组合筛选。
- [x] 筛选条件保存、结果总数、清空、失败重试和纯文本原文按需加载。
- [x] 特殊字符按解码后的主题、发件人和正文搜索，不搜索 JSON 键。
- [x] 不把同来源同名但 ID 不同的活动合并；标题回退仅接受唯一的跨来源候选。
- [x] 提交状态读取失败不抹掉已验证状态；失败观察仍保留在证据中。
- [x] 单个本地资料失败不阻断其余本地来源及远程采集。
- [x] Git 发布检查与 Windows CI 配置。
- [x] 干净 Windows CI 暴露的启动探测和 GUI 回调释放问题，均补确定性回归后修复。
- [ ] 远端 CI 实际运行与 PR 审阅；源码测试不代替正式运行版或真实提供方验收。

## 迭代 2：真实来源核对与候选分流

- 为学校连接、课程读取、作业／测验及提交状态分别展示完整性与失败原因。
- 将未核对邮件候选从正式作业中分离；人工确认后成为邮件待办。
- 原邮件与关联事项双向跳转。
- 统一 Moodle 非作业／测验活动的实例 ID 与课程模块 ID。
- 修复飞书重复事件取消后恢复时对已删除事件 ID 的更新问题。

## 迭代 3：稳定课程目录与用户标记

- 站点＋课程 ID 标识课程，保留原名，支持简称和颜色。
- 多标签用于邮件、作业和资料；标记与采集事实分开保存。
- 同名课程隔离，既有事项 ID、提交状态和映射保持不变。

## 迭代 4：资料目录、筛选与界面减负

- 课程 → 具体活动／链接联动，类型、状态、标签、关键词和日期组合查询。
- 资料按目录显示，只保留元数据与原始链接，不全量下载课件。
- 手机端紧凑导航、可折叠筛选、按页面加载；刷新不打断输入。

## 交付验收

每轮先补失败回归，再修复、复核和合并。新便携版另行构建，在复制数据上验证升级与回滚。Google 发布／长期授权、Apple 回传、飞书消息回执与第二台 Windows 接管分别进行真实环境验收。

模型分析保持关闭；外部执行模式不随 UI 或标记修改自动切换。
