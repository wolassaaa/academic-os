## 首轮迭代：来源可靠性与邮件全库查询

### 改动

- 邮件进入主导航；全库服务端分页、账号／关键词／收件日期组合筛选、总数、保存条件、清空及失败重试。
- 邮件正文按需读取且按纯文本显示；旧 `/mail` 接口保持兼容，新增 `/mail/search` 返回分页元数据。
- 解码后的主题、发件人、正文支持引号／反斜杠／LIKE 通配符的字面搜索；极端日期返回 422。
- 同来源不同 ID 的同名活动不再误合并；唯一跨来源标题候选保持兼容。
- `unknown` 提交观察不再抹掉已有验证状态，真实重新开放仍可回到 pending。
- 单个本地资料失败独立记录，不阻断其他资料和远程来源；部分失败继续进入持久化重试。
- 新增源码发布检查、Windows Python 3.11／3.14 CI、工程路线和复核记录。

### 本地验证

- 原始基线：150 tests passed。
- 新增回归先复现：8 failed, 16 passed（邮件特殊字符／日期上界及来源可靠性用例）。
- 当前完整测试：183 passed。首次 Windows CI 暴露启动探测 ReadTimeout 和 Tkinter Variable 延迟析构问题；新增确定性回归先得到 2 failed，再修复至 2 passed，保留失败日志。
- GUI 退出时释放自引用轮询闭包，避免 Tkinter 状态被后续 worker GC 析构；启动探测在原有预算内重试短暂超时，不延长超时预算或跳过真实 HTTP 断言。
- Ruff、JavaScript 语法检查通过。
- 原有桌面／手机／远程只读浏览器回归通过。
- 新增 123 封隔离邮件浏览器场景通过：翻页、全库查询、条件保留、空结果、日期边界、重试和无日期。
- Python wheel 构建通过。仅验证源码包，不把它当作已重建的免 Python EXE。

### 后续与边界

飞书已取消实例恢复、Moodle 非 assign／quiz 模块身份、来源诊断、邮件候选分流、课程目录／标记和运行版交付已建立 Issues。首轮不修改真实业务库或授权，不切换外部执行模式。
