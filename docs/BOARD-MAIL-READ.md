# 新看板邮件阅读（P1 / v0.4）

服务启动后打开 `/board/mail.html`，或使用看板导航“邮件简报”。仅展示现有服务已收集的邮件，不触发邮箱同步，不代表邮箱完整性已经核实。

## 已接入
- 服务端分页（20 封一页）、主题/发件人/正文搜索、账号、全部/待核对/已忽略筛选，以及按业务时区的收件日期范围。收件日期不冒充任务截止。
- 500 字原文摘录、截断提示及可折叠的完整原文（长邮件默认收起，让候选证据先可见）；原文仅按文字展示，不执行 HTML、不加载外部图片。明确不是 AI 总结。
- 同一邮件展示多个关联候选、逐条日期证据、未知截止与冲突状态。P1 的确认/忽略/恢复仍跳转旧工作台，P2 单独接入写操作。
- 正式事项与关联原邮件双向跳转；返回原邮件保留搜索、账号、核对和收件日期筛选。待核对/已忽略候选深链选择正确的旧工作台分类，保留原 ID。
- 首次加载、空结果、404、登录过期、远程阅读限制、刷新失败和新查询失败分别处理；旧响应不覆盖新查询。仅同一查询刷新失败保留旧结果，且标明过期。

## 数据与交付

复用 GET `/api/v1/session`、`/mail/digest`、`/mail/{key}` 和 `/board-context`。没有新增后台接口、模型、数据库表、浏览器持久缓存或轮询。远程页面不探测邮件/原文接口。生产读取失败不回退到虚构样例。

验收使用临时 SQLite 与真实本地 HTTP，覆盖桌面1440、手机390、分页/组合筛选、超长原文、HTML字面显示、多个候选、未知截止、精确深链、双向返回、错误恢复及请求乱序，并检查零写请求/外部请求/CSP/JS错误。现有243项及既有浏览器回归继续验证。

源码更新不代表真实服务已重启或便携 EXE 已重建。下一轮接逐条核对的真实写入及独立回执，继续保护未确认候选不产生截止提醒。
