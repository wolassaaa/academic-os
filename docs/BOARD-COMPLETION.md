# 看板 v0.2：先把使用闭环做实

## 已接入

- 本地卡片、列表和详情均可标记完成。确认窗默认聚焦取消，提交中锁定按钮；收到服务回执后才更新界面。刷新、重开详情和旧工作台保留真实完成状态。
- 完成不是向学校提交作业。既有后台会处理系统学习日历事件与待发提醒；确认窗明确说明，不把事项回执冒充日历同步成功。
- 截止分别显示已核对、待核对、未知和冲突；原证据作为纯文本显示，注明来源截止和采集时间。来源异常给出检查来源入口，读取时间不冒充同步时间，成功同步也不保证数据完整。
- 工作台链接直接打开指定事项，包含已关闭事项；连接与来源管理跳到对应页面。
- 独立演示中，移出重点仅放回待办池并重排；只有删除使用碎纸动效。保留确认、撤销和回收站。

## 权限与恢复

复用 PATCH `/api/v1/items/{id}`、原确认权限、CSRF 和 expected_version。可选 `Idempotency-Key` 长度为 1–200，记录在既有 operations 表，不迁移数据库；不带该头的旧调用保持原有行为。同键同请求返回原回执，不重复版本、审计或后台任务；同键不同请求或新键旧版本返回冲突。权限检查先于幂等重放，默认 Agent 无确认权限，远程不开放 PATCH。

客户端只在内存保存 CSRF 与未决请求键。断线后提示“结果暂未确认”，允许原请求核实重试；不自动换版本覆盖。页面关闭会丢弃内存请求键，重新打开先读取服务事实。冲突必须刷新重新核对；会话过期隐藏事实；刷新失败保留已确认回执、标记过期并停用后续完成操作。没有乐观成功、自动后台写入或常驻轮询。

## 验收与下一轮

`python -m pytest -q`、`node tests/board_completion.test.cjs .`、`python tests/board_completion_browser.py --screenshots <目录>` 覆盖临时真实 HTTP、桌面/手机、取消、刷新持久化、权限、并发、回执丢失及精确跳转。其他旧浏览器回归继续运行。

下一轮按顺序推进：
1. 独立保存个人重点偏好，区分紧急与用户主动选中；处理逾期、无截止和无结果边界。
2. 邮件简报真实读取 → 逐条核对 → 关联跳转，持续保护未确认候选不产生截止提醒。
3. 日历真实阅读 → 安排草稿 → 用户确认写入 → 单独同步回执，明确安排不等于完成。
4. 小任务持久化与父子完成规则；再做 Hermes 事实读取和受控操作。
5. 测量启动、内存、大列表性能和备份恢复；有实测瓶颈再优化存储，不先更换 SQLite。
