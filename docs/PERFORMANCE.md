# 轻量化测量与数据库选择

## 本轮选择

保留 Python 内置 SQLite + WAL，没有新增 PostgreSQL/Redis/向量库进程，也没有把 Hermes 运行时塞进便携程序。单机本地数据与短事务适合嵌入式存储；这与 [SQLite 官方适用场景](https://www.sqlite.org/whentouse.html) 一致。每连接缓存从默认约 2000 KiB 改为 1024 KiB（负值单位见 [cache_size 文档](https://www.sqlite.org/pragma.html#pragma_cache_size)），临时存储使用文件，事务、完整正文及历史记录保留。

新增收件日期表达式索引、账号＋邮件 ID 身份索引，以及标签关系反向索引；日期排序不再临时构建 B-tree。索引和持久化增量游标会增加少量磁盘，换取更快查询和可靠漏读追踪，不把“数据库文件缩小”作为已达成结果。

## 本机可复现实测（2026-10-14）

同一 Python 3.14.3、同样 10,000 封合成邮件（每封约 4,500 字符正文），每次读取 50 封元数据，独立子进程、各跑 30 次。基线 fb99e6d 与本轮工作树，无真实邮件、网络或模型调用。测量脚本及 JSON 输出在交付 artifacts/iteration-3；Win32 GetProcessMemoryInfo 测量该基准进程，**不是完整 GUI 或 Hermes 的常驻内存**。

| 指标 | 基线 | 改版 |
|---|---:|---:|
| 查询中位数 | 44.277 ms | 4.350 ms |
| 查询 P95 | 47.769 ms | 5.880 ms |
| 查询 Python 峰值分配 | 121.5 KiB | 121.7 KiB |
| 基准进程 private memory | 20.19 MiB | 18.77 MiB |
| 基准进程 peak working set | 76.71 MiB | 75.96 MiB |
| SQLite 文件 | 46.29 MiB | 47.46 MiB |

查询约 10.2 倍快；该基准 private memory 下降约 7%。Python 分配没有显著改善；磁盘增加 1.17 MiB。耗时和内存受机器、文件缓存、并发影响，不是跨机器保证。

## 其他实装减负

- 后台摘要由每 2 秒重写改为最多每 60 秒一次；显式 GET /summary 与 export 作业仍即时生成，最坏自动摘要延迟约一分钟。确定性测试验证 0/59/60 秒写盘行为。
- 导入的成绩／资料正文只在“运行记录”页拉取，不再跟随所有页面定时刷新。邮件正文继续按需读取，简报每页最多 50 封，每封最多 4000 字符；默认 20 × 800。
- 便携版使用隔离运行依赖环境，不打包测试浏览器、pytest、ruff，不增前端框架。
- 本轮不删除原邮件、历史审计或回执，不降低事务持久性，不自动切换外部执行模式。

## 下一步优先级（自评）

1. 邮件与 Moodle 采集队列解耦、分来源时延指标：现在学校慢请求仍可拖延下一轮采集，默认 300 秒轮询不是即时 Push。先实测实际来源，再决定独立轻量任务还是 Gmail Push；不盲目把所有来源调到 30 秒。
2. 稳定课程目录／学期身份：已有多标签和课程作用域，下一轮将真实 Moodle course ID 映射到目录，明确归属后再自动建议标签；不凭同名课程合并。
3. Hermes 部署端调度、反馈回执：已提供持久化 feed 和 MCP；Hermes 真正运行后再按消费游标配置主动反馈，避免第二个采集器和重复提醒。
4. 修复现有已登记的非 assign/quiz 活动身份与飞书取消后恢复事件问题；继续独立回归与 PR，不在标签变更中暗改。
5. 数据量达到数十万邮件后，再测 FTS5 搜索与正文分离／压缩收益。当前不为了“更轻”的名义承担全库格式迁移和恢复风险。
