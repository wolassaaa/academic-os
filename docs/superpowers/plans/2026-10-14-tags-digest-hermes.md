# 课程标签、邮件简报与轻量化（用户授权自主取舍）

## 需求与取舍

用户要在早上查看能运行的结果：事项可以归属课程、某份作业、小组及多个自由标签；邮件来不及读时仍能看到内容简报；Hermes 管理同一事实库；程序应更轻量。沿用现有界面与业务 API，不增加数据库服务或第二个常驻 Worker。

1. 标签：SQLite 独立 tags / item_tags 关系；kind=course/assignment/group/custom，scope 表示课程或学期上下文，不以同名课程猜身份。标签多选、组合筛选、重命名、归档（保留历史）、版本校验、幂等及审计。同步不修改标签。现有 course 显示不自动改名或推断分组。
2. 邮件简报：确定性内容摘录而非虚构模型总结；主题、发件人、收件时间、正文片段、候选状态与原文入口。分页与截断均显式说明，原文继续按需查看。默认只在本地；自动日简报默认写工作台，不新增外部正文投递。邮件反馈采用持久化增量 feed 游标，延迟到达的旧邮件也按本地采集顺序追踪；消费确认独立于正文读取，避免读即丢失。已有采集失败与心跳显式返回。
3. Hermes：官方 MCP stdio 适配现有本地 API；增加标签、筛选、简报、增量邮件工具。提供实际绝对路径配置及操作说明，官方客户端握手和真实 HTTP 集成验证。默认仍不允许确认待办、日历写入或外部发送；Hermes 不直接访问 SQLite 或邮箱凭据。没有 Hermes 安装时交付可导入配置，不将测试 MCP 握手说成 Hermes 模型已经在线。
4. 轻量化：保留内置 SQLite/WAL；限制每连接缓存及临时存储、增加查询索引，避免额外数据库进程；页级按需加载、减少未变化摘要写盘。记录合成数据的查询时间、峰值内存和文件体积，不承诺未经测量的收益。完整正文保留，不用删历史换取体积数字。

## 实施与验收

- 数据／标签：先失败测试；多标签、作用域同名隔离、版本冲突、归档、同步保留、备份重启；再实现模块、API、页面。
- 简报／feed：先失败测试；无日期、截断、多账号、分页、延迟到达、确认游标、权限、远程无正文；再实现模块、API、工作台日简报。
- MCP／性能：旧接口兼容，新增工具通过官方客户端与实际业务服务验证；基线和改版同数据测量，浏览器桌面／手机回归。
- 全量测试、一次整分支复核、Windows CI、叠加 PR（base=iteration/mail-triage），新版便携构建和独立回滚验证；当前 PR8 不自动合并。

## 意图与界面

面向忙于课程、漏读邮件的学生；先认清“这件事归哪门课／哪组”，再处理。保持现有纸白、深绿工作台，不引入前端框架或大型可视化库。标签筛选紧邻事项搜索；邮件简报在收件箱页按需展开；管理标签放入高级工具。
