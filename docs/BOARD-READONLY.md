# 新看板：正式事项读取合同

> 本文记录 v0.1 的读取合同；v0.2 增加本地完成操作，具体权限、恢复和日历语义见 [完成闭环](BOARD-COMPLETION.md)。远程读取限制继续保持。

## 入口

运行更新后的现有服务，在同一地址打开 `/board/`；旧工作台 `/` 保留登录、连接管理、核对和安排等写操作。旧工作台导航增加“新看板”，远程标记只读。演示站 `8897` 独立保留，不连接账户。

本轮提供本周、全部待办、任务详情、设置与来源状态五页，沿用 Material 和整卡课程色。本周默认六张卡，可展开全部重点；待办流仍在正常文档布局中。没有新框架、CDN、字体、数据库迁移或常驻轮询。

## 数据合同

- `GET /api/v1/session` 判断已登录、本地/远程和初始化状态；不存储凭据或 CSRF。
- 新增只读 `GET /api/v1/board-context`，认证后仅返回业务 `timezone`、服务 `now` 和暂为 `null` 的 `semester`。不读取完整账户配置。
- 本地读取现有 `GET /api/v1/items?view=formal` 完整数组与 `GET /api/v1/health`；当前事项接口没有分页。将来改分页时须同步修改完整性合同，不能对一页数据做全局筛选。
- 远程只读取已有脱敏 `GET /api/v1/dashboard`；不开放远程 items、health、原文证据或任何新写接口。
- 日期筛选按业务时区解释截止日期，含首尾两天。无截止默认保留，混合来源不会因邮件 pending 标记被隐藏。
- 正式事项中的已完成/已提交/已取消退出待办。安排时间不等于完成；展示不修改原 ID、版本、截止、安排或日历映射。
- 当前正式接口没有子任务和学期配置，小任务显示“未提供”，学期显示“未设置”；不使用演示进度替代。

## 异常与访问

首次加载、真实空列表、筛选无结果、请求失败和登录过期分别显示。手动刷新失败保留已读事项并标记过期；登录过期清除页面上的事实并返回登录入口。来源状态单独失败时仍显示已经取得的正式事项，不宣称同步正常。

生产 bundle 不包含 preview-adapter 或 preview-state；读取失败不退回虚构数据。CSP 保持 `script-src/style-src/connect-src 'self'`，遗留静态 style 属性已编译为本地 CSS 类。动效只使用本地 GSAP core，尊重减少动态效果。

## 验证与后续

`python -m pytest -q`；`python tests/board_browser_check.py --screenshots <输出目录>` 使用临时 SQLite 和两个真实 HTTP 服务测试桌面、手机、远程、登录过期、纽约午夜边界、混合来源、刷新和 CSP。

验收只使用临时数据，不触发真实外部日历写入。v0.2 已接本地完成；后续依次接日历与邮件真实阅读，再单独接逐条核对和安排写入；写入继续复用 CSRF、确认权限、版本与幂等。
