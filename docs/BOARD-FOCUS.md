# 看板 v0.3：我的重点与自动推荐

## 使用

- 卡片、待办列表和详情提供“设为重点 / 移出重点”。未设置偏好的事项沿用截止与优先级自动推荐；主动选中的卡片优先展示并标为“我的重点”，其余标为“自动推荐”。
- 移出重点只放回待办池，不删除、不完成，不改变截止、优先级、安排、业务版本、提醒或日历事件。逾期总提示独立保留，不因移出重点或筛选而静默消失。
- 无截止任务也可设为重点；搜索与日期筛选仍生效。日期范围不会把已移出的事项重新提升为重点。详情可“恢复自动推荐”。
- 选择保存到现有 SQLite meta，按本地登录用户隔离，刷新、换页面及重新启动服务后可读取。不增加数据库表或浏览器持久存储；来源同步不写此偏好。

## 操作与异常

新 GET/PUT `/api/v1/board-focus` 仅在本地开放，使用现有浏览器登录、CSRF、确认权限；Agent 即使带 confirm scope 也不修改个人偏好，远程没有接口。PUT 包含 item_id、mode（focus/pool/auto）、expected_revision 与 Idempotency-Key。独立偏好修订号不冒充事项版本。

服务确认后才移动卡片；并发冲突要求刷新重新选择。提交结果丢失可用同键核实重试，不自动覆盖其他页面的选择。偏好读取失败时保留已有选择、禁用修改并提示；首次失败只展示自动推荐，不把默认值写回服务器。会话过期隐藏反馈和事实。

已关闭或未确认邮件候选不进入个人重点。旧偏好记录不删除历史，只在当前活动正式事项中应用。重点不等于日历安排，完成仍使用上一轮的独立确认闭环。

## 验收与下一步

新增后端、纯模型与真实 HTTP 浏览器测试覆盖持久化、用户隔离、CSRF、Agent/远程、并发冲突、重复重放、无截止、逾期、日期范围、恢复自动、断线重试和读取失败。使用临时数据库，未触及真实邮件或日历。

下一轮：邮件简报真实阅读及逐条核对入口，再做日历安排闭环。个人完成与学校提交的来源变化语义单独复核。当前便携 EXE 不随源码自动更新。
