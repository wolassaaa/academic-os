# 历史与重新打开

## 使用
全部待办提供“待完成”和“已关闭/历史”视图。历史可筛选全部已关闭、已完成、已提交、已取消，以及个人完成但学校来源明确未提交的事项。关键词、课程和截止日期筛选继续有效，链接保留这些筛选。历史按事项最近更新时间倒序；不是完成时间，不伪造旧数据的完成时刻。关闭不是删除，原 ID、截止与邮件关联保留。

关闭事项的列表行和详情均可显式重新打开，确认后个人状态变为待完成。学校来源提交事实不被撤销。已提交显示为“来源记录已提交”或“自行标记已提交”，不混淆出处；详情保留逐来源事实。重新打开后可通过待完成视图找回；返回历史沿用原筛选，因此刚重开的事项不再在历史列表内。

## 待提交提示
仅当个人状态是 explicit completed、事项仍为 completed，并有 moodle/canvas 来源明确 not_started/pending 时提示。多来源中有一条未提交则提示“有来源仍显示未提交”，不覆盖其他来源事实。缺失、unknown、进行中、历史完成和邮件文字不推断提交状态。远程脱敏视图不暴露这些原始事实。

## 权限与一致性
沿用 PATCH /api/v1/items/{id}，仅发送 status=pending、expected_version 与会话 CSRF、幂等键。关闭事项的状态改动必须有 confirm 权限，默认 Agent 的 read/draft/sync 凭证不能重新打开。远程仍无修改路由。

对话框默认聚焦取消；Esc 不保存。网络结果不明时保留同一请求体和幂等键，用户决定核实重试；409 要刷新重新核对，不按新版本自动覆盖。收到服务回执后才移出历史。刷新失败保留已确认结果，数据过期时禁用写入。

## 边界
本轮不新增通知策略或改变学校提交事实，不引入 AI/新框架/新表/数据库迁移。重新打开沿用现有安排、日历队列与通知去重行为，不保证生成新的截止提醒；此前完成可能已关闭旧提醒，这一策略需另行评审。页面中的“已关闭”不是回收站。本轮是源码迭代，不是已安装的新便携 EXE。
